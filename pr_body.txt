Fixes #756

## Description
When the AST parser encounters a composite type (like a map, slice, channel, or function) while evaluating a signature filter, it currently triggers a fatal `Unimplemented` error, which crashes the entire build. 

This behavior contradicts the documented behavior in `docs/rules.md`:
> **Unsupported type expressions:** Complex type expressions — `chan`, `func`, `map`, slice (`[]T`), and non-empty interface literals — cannot be matched by type-name filters. If a parameter or return value uses one of these forms, the filter will never match it.

This PR removes the fatal crash and simply returns `false` (no-match) for unsupported composite AST nodes, aligning the tool's runtime behavior exactly with the documentation.

## Changes
- Removed the `util.Unimplemented` call in `typename.go`'s `matches` default switch case.
- Added comprehensive unit tests in `typename_test.go` to ensure that `map` and `slice` (`[]T`) types correctly return `false` without panicking.
